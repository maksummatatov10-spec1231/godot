## Что проанализировано

- 5821 файл, 2857037798 байт, включая вложенные архивы и извлечённые копии;
  5192 уникальных SHA-256, 158 групп повторов. Повторные форматы/файлы не считаются
  отдельными игровыми объектами.
- Безопасно извлечены 29 ZIP и 1 RAR; RAR — через node-unrar-js/WASM, а не
  неработающую в этой среде native libarchive. Проверки защиты extraction — в tests.
- 2773 пути моделей / 2763 уникальных хеша проверены настоящим Blender:
  **2762 успешно, 1 ошибка**. Полигональность, bounds, armatures, действия/анимации
  сохранены в `blender-models.jsonl`; это не проверка каждого клипа в движении.
- 552/552 аудиофайла декодированы, измерены длительность/уровни/клиппинг.
  Прослушивание каждого файла не выполнялось — нельзя путать decode с оценкой звука.
- Просмотрены 9 листов текстур и 3 обзорных листа геометрии. Все 89 preview-файлов
  созданы; не заявляется ручной просмотр каждого из них. Превью геометрии —
  изометрические проекции импортированных мешей, **не textured game renders**;
  могут включать demo/helper geometry, не гарантируют видимость всех материалов.
- 783 binary/sidecar записи и 275 записей потенциальных проблем зависимостей.
  Полные результаты — [каталог](assets/INDEX.md), `dependency-issues.json`,
  `binary-inspection.json`, `audio-inspection.jsonl`, `model-preview-index.json`.

### Найденные проблемы

1. `Modular SciFi .../glTF/Decals/Decal_Line_90.gltf` требует отсутствующий
   `Decal_Line_90_001.bin`. Соседний `Decal_Line_90.bin` совпадает по ожидаемому размеру
   1128 байт, но **не подменён** и не объявлен доказанным исправлением.
2. 182 glTF-файла содержат 840 ссылок, не разрешающихся относительно их папок.
   Для 836 есть одноимённые кандидаты в том же наборе: при переносе нужно сохранять
   структуру/осознанно исправлять пути. Четыре unmatched — этот buffer и normal maps
   `female/T_Eye_Normal_png.png`, `male/T_Hair_1_Normal_png.png`, `male/T_Eye_Normal_png.png`.
3. 93 записи `res://` из Godot-наборов — эвристические: исходный root проекта может
   отличаться, не все эти ссылки обязательно повреждены.
4. Материалы/текстуры, animation retargeting, root motion и VFX нужно проверять уже
   на выбранных для игры моделях/сценах. Массового игрового импорта ещё не было.

## Blender

Используется именно поставленный Blender 5.3, не экспериментальный PyPI bpy.
Проверены `--version` и реальная операция с мешем, затем массовый импорт моделей.
Для недостающих системных библиотек подготовлен отдельный runtime-каталог:
источники/SHA-256 — `docs/blender-runtime-sources.json`. Старые совместимые библиотеки
используются как sandbox fallback, не рекомендуются как системный production runtime.

`tools/blender_external.py` выставляет LD_LIBRARY_PATH и **отключает autoexec**.
Встроенный `rig_ui.py` в Mannequin_F намеренно не исполнялся. Для неизвестных .blend
нельзя разрешать автоматический Python-код только ради удобства импорта.

## Как восстановить после потери внешних папок

1. Сначала попробовать загрузить два оригинала на обычной машине. На данной
   sandbox-сети прямые Google/GitHub binary CDN были недоступны; повторять те же
   неработающие URL без изменения условий бессмысленно.
2. При том же ограничении использовать `docs/transfer_archives_colab.ipynb`:
   он читает оригиналы в Drive и создаёт части по 90 MiB и новый manifest.
   Текущий connector-limit — 100 MiB, не лимит размера исходного ассета.
3. Скачать **новые** части во внешнюю папку. Старые ID из
   `assets/transfer-manifest.json` — историческое свидетельство успешной передачи;
   эти временные файлы теперь в корзине, поэтому не считать их актуальной download-ссылкой.
4. `python tools/assemble_asset_transfer.py --help`: сборщик сверяет каждую часть,
   размер и общий SHA-256; вывод внутрь репозитория и случайная перезапись запрещены.
5. Извлечь оригиналы с `tools/extract_asset_library.py` во внешнюю библиотеку.
   Вложенные RAR обрабатываются `tools/extract_asset_rar.cjs`; установить его npm
   dependency вне игрового проекта, не коммитить node_modules.
6. Восстановить поставленный Blender и недостающие shared libraries на основе
   проверяемых source/hash из `blender-runtime-sources.json`, либо поставить
   современные системные библиотеки на полноценном хосте. Не исполнять .blend autoexec.
7. Аудит воспроизводится инструментами `catalog_assets.py`, `inspect_assets_blender.py`,
   `inspect_asset_audio.py`, `asset_dependency_report.py`, `publish_asset_catalog.py`.
   У каждого — `--help`; отчёты писать во внешнюю папку, компактную публикацию — в docs.
8. Плагины уже сохранены в Git. Для переустановки из архива предназначен
   `install_godot_plugins.py`; текущие addons не перетираются автоматически.

Временные части после новой успешной передачи можно снова переместить в корзину,
оставляя только оригиналы. Никаких новых Drive-файлов эта инструкция сама не создаёт.
